# VexTab 6 engraving and language baseline

**20 November 2026 · VexTab 6.0.0 · grammar v2 · VexFlow 5.6.1 in the released bundle**

Start with three scores. An eighth-note melody over a sustained bass needs one shared system. A singer needs one legible lyric baseline across the system. A guitarist who can read an explicitly beamed phrase on screen should be able to print it. All three expose gaps in the released VexTab. The first already works in a direct VexFlow control on the **same dependency**.

Establish musical and visual controls first. Close screen/print losses and introduce a shared ensemble projection before expanding page layout and the notation vocabulary. Develop an editable repertoire alongside those steps. A musician should be able to change one passage and get a faithful conductor score, individual parts and playback from the same source.

## Where engraving decisions live

The v2 reader and compiler already represent exact within-bar time, head marks, voice ownership, ranges and pattern expansion. `projectScoreV2` lowers **one instrument at a time** to `ParsedScore`. `renderScore` builds a fresh EasyScore composition from that projection. `renderScorePart` builds a new VexFlow `Publication`. `Div` stacks the individual renderings and `Player` can start all instruments together. A piano or a paired guitar staff/TAB already gets a shared system within its instrument. Preserve the compact guitar syntax, independent voices and common playback origin. ### An ensemble and a printed edition

1. **Name the musical owners.** Add optional stable part and staff IDs, full and short instrument names, instrument profile and written-to-concert interval. Give events, heads, measures and spans unambiguous references across parts and pattern expansions. Keep part index selection for current callers. The rhythmic voice, displayed staff and sounding instrument must be independently identifiable.
2. **Build a conductor composition.** Start with equal measure spans across parts. Project all voices onto one rational timeline, group the piano or paired TAB inside the ensemble, then hand VexFlow one set of staves and boundaries. Its formatter chooses common horizontal positions and system breaks. Let each extracted part recompose from the source descriptors. Preserve today's single-instrument calls and offer an explicit conductor view.
3. **Specify unequal parts and polymeter.** Current parts may have different local bar counts and meters. Two bars of 3/4 and three of 2/4 meet after six quarters. Use absolute rational time for the meeting point and retain each local bar ID. Establish policy for a shorter tacet part, pickup and delayed entry. The general EasyScore composer requires aligned measure arrays and common spans. Start with the supported shared-meter case. Provide a located conductor-view diagnostic for unsupported grids while independent parts and playback remain usable. Test generalized polymeter against a direct native prototype before promising pagination. [Composition contract](https://github.com/vexflow/vexflow/blob/5.7.0/docs/easyscore.md) · [Independent-meter study](https://github.com/vexflow/vexflow/blob/5.7.0/docs/vf6/m6.md)
4. **Describe editions in the source.** Put physical paper size, staff size in mm, margins, titles, header/footer, page numbers, system gaps, forced breaks and preferred/forbidden turns on a score or part edition. Define the difference between “start a page at bar 9” and “turn after bar 8.” Select cues by instrument and source measure. A cue stays silent and lets its player retain the written rest. Pass validated options to `Publication` and return its typed overflow, turn and excluded-anchor diagnostics. [Publication options](https://github.com/vexflow/vexflow/blob/5.7.0/src/publication.ts) · [View and turn rules](https://github.com/vexflow/vexflow/blob/5.7.0/src/publicationview.ts)

The following **design sketch** is for an authoring trial. The declaration names are provisional. The intended outcome is one two-staff concert score and a B-flat clarinet part with its own paper and written pitches. Here the author enters written pitches and the instrument interval supplies the sounding pitch. The written D and the cello’s C should sound in octaves.

```text
meter 4/4
staff clarinet { name "Clarinet in B-flat" shortName "Cl." sounds -2
  :w D4 | :w E4 |
}
staff cello { name "Violoncello" shortName "Vc." clef bass
  :w C3 | :w D3 |
}
edition conductor { parts (clarinet cello) pitch concert paper A4 staffSize 7mm }
edition clarinetPart { parts (clarinet) pitch written paper Letter margins 16mm }
```

Trial the syntax by adding a third player, moving a rehearsal mark, extracting one hand, forcing a page break and transposing the clarinet. Ask an author to identify the affected source without reading JavaScript. Keep the one-line guitar form and aliases. A typo, duplicate ID, inconsistent timing, dangling head reference or impossible page choice should name the part, measure, source range and expansion site where applicable. Keep bounded expansion and the existing aggregate limits, including 64 KiB of source and 4,096 expanded events, in the grammar and generation tests. ## Repertoire for the first demos

Publish four small, complete musical passages. Give each an editable `.vextab` source, a citation to the exact edition and bars, a reference image or link, a screen view, downloadable print and a brief listening or reading task. State which fingerings, TAB positions, chord symbols or arrangements VexTab’s editor added. Record the terms for the specific edition, transcription and any distributed images or recordings separately. Keep the current guide studies as small regression controls.

| Work and passage | Score to build | What a player should be able to verify |
| --- | --- | --- |
| **Fernando Sor, Op. 35 No. 22, opening eight bars** · classical guitar | Transcribe the sustained melody and moving accompaniment. Add an explicitly editorial TAB realization. Mutopia identifies N. Simrock as its source, Glen Larsen as maintainer and CC BY-SA 3.0 for its edition. Credit and carry the terms if adapting that transcription. [Score, LilyPond source and MIDI](https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=1850) | Hear the held pitches while the accompaniment continues. The two voices remain legible in standard notation. A fingering belongs to its chord head. Extracted TAB retains the chosen strings and frets. |
| **Scott Joplin, Maple Leaf Rag, complete first strain** · ragtime piano | Use the 1899 John Stark & Son score for both hands, syncopations, bass leaps and written repeat. Provide an independent left-hand practice part. [Levy Collection score](https://levysheetmusic.mse.jhu.edu/collection/171/085) · [Library of Congress description of the 16-bar strain](https://www.loc.gov/collections/ragtime/articles-and-essays/classic-rag/) | Check the attack after a syncopation against the bass, stem directions in a chord, alignment of the two hands, and the repeat entry. Move a system break and follow the phrase through it. |
| **W. C. Handy, The St. Louis Blues, first sung chorus** · vocal blues | Transcribe the vocal line and piano accompaniment from the 1914 Pace & Handy edition. Make a singer’s edition with lyrics. Mark the reduced chord symbols as editorial. The library identifies the five-page voice/piano score as item 011446402-1914. [Mississippi State University score](https://scholarsjunction.msstate.edu/cht-sheet-music/2668/) | Read every syllable through a line break, see the chord change over the correct attack and follow a sustained word without crossing another verse or the accompaniment. Compare pitches and word underlay against the edition. |
| **Joseph Haydn, Op. 76 No. 3, movement II, theme and first variation** · string quartet | Set both violins, viola in alto clef and cello. Give each player a named part and a useful turn. The OpenScore entry (20428156) supplies score, MusicXML and four PDFs of individual parts. Credit OpenScore for its CC0 transcription. [Work catalogue](https://fourscoreandmore.org/openscore/stringquartets/) · [Corpus and license](https://github.com/OpenScore/StringQuartets) | Follow the tune between players. All four staves share attacks and barlines in the conductor view. The viola and cello can reflow independently while keeping rehearsal and source references. Compare one extracted phrase from each part against its published counterpart. |

**Next instrument test.** Use a short final-strain excerpt of Sousa’s *The Stars and Stripes Forever* for piccolo, B-flat clarinet, bass and drums. Label the reduction and keep the source parts’ pitches. This fills the transposing-winds and percussion gap left by the first four demos. A conductor and a clarinet player should be able to compare concert and written pitch on the same beat. [U.S. Marine Band full score](https://www.marineband.marines.mil/Portals/175/Docs/Audio/Complete%20Marches%20of%20JPS/Volume%203/Scores/53_StarsAndStripesForever.pdf) · [Library of Congress parts](https://www.loc.gov/resource/music.musihas-200028215/?sp=1)

## Delivery order and exit criteria

| Milestone | Work | Exit criterion |
| --- | --- | --- |
| **M0 · Capture the release** | Check in the capability inventory and short fixtures. Record an immutable V6 browser reference, a native ensemble control and the first rehearsal-size crops. Qualify 5.7.0 in an isolated dependency trial. | Another developer reproduces the lyric loss, lyric baseline jump, part refusals and two-instrument wrap, and restores the original row map on resize. Each inventory family has an owner, an evidence link and a disposition. |
| **M1 · Preserve authored music** | Fix silent mark loss, bring explicit beams, silent positions, accidentals and head marks through publication, then address frames and TAB-specific cases. Compare each drawing workaround with a native control. | The `Slow River` lead sheet, Sor opening and small beam/skip cases print with the same musical content as the screen. Each surviving fallback has a bounded case and a native replacement criterion. |
| **M2 · Align the ensemble** | Introduce named instruments and staff groups, one conductor projection, independent part selection and written/concert pitch. Run the quartet theme early. | Four staves share onsets at both widths. Four extracted parts retain IDs and independent wraps. A B-flat test sounds the same pitch from conductor and player views. Incompatible grids give a located diagnostic. |
| **M3 · Author paper editions** | Add page-level grammar and mapping to `Publication`. Add headings, physical spacing, part cues, rest compression and turn constraints. | Generate A4 and Letter conductor and part PDFs from one source. Measure margins and pages, verify cue silence and identify an impossible turn at its source. Approve the quartet theme and variation on paper. |
| **M4 · Expand musical vocabulary** | Ship proven 5.7 mappings with typed endpoints, verse lanes, dynamics, grace/ornament support, tremolos and guitar techniques in small slices. Add playback routing and performed repeats with an explicit compatibility mode. | Each operation has parser, native, screen, part and relevant player evidence. The Sor, Joplin and Handy excerpts are musically reviewed. Unsupported syntax or combinations give actionable ranges. |
| **M5 · Qualify and teach** | Finish the four demos, update the v2 guide and API reference, publish the capability inventory with deliberate limits, and run browser, print, access, performance and clean-package checks. | A musician can edit, rehearse, select a source event and print a part for every demo. Every visual change has a reviewed reason. The report identifies any remaining upstream dependency and its smallest failing score. |

Start implementation with the two-mark lyric and the four-bar ensemble. The lyric case catches loss between two existing representations. The ensemble case proves how much VexTab can gain from a native layout path it already ships.

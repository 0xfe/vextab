Import a LilyPond score

Start with a two-bar phrase. The first attack is a C-major chord. The next two notes share an eighth-note duration. In the VexTab editor below, the same three chord heads sit inside parentheses and each octave is written out.

meter 2/4
staff {
  key C
  voice upper { :q (C4 E4 G4) :8 D4 E4 |
    :h F4 | }
}

Change f2 to g2, convert the source, then play the result. Only the long note in the second bar should move. Changing that half note to a quarter leaves the measure short and produces a timing diagnostic.

Choose the music to read

With multiple \score blocks, select one by its zero-based index or by 'print' or 'midi'. The reader resolves variables, relative pitches and known pitch-language includes. Give it the text of your own includes by their source names. A guitar edition written on a conventional staff can request paired notation and TAB with guitar: true.

Computed Scheme music and unresolved includes stop conversion. See Read the diagnostics for the difference between an omitted engraving detail and a passage that cannot be timed.

Import a MusicXML score

Read a dotted quarter and an eighth in 2/4. Two divisions make one quarter note, so the first attack lasts three divisions and the second lasts one. VexTab writes those values as :q. and :8.

meter 2/4
staff {
  name "Flute"
  key C
  voice upper { :q. G4 :8 A4 | }
}

Change the last <step>A</step> to B and convert again. The second pitch moves up and its onset stays three eighths into the bar. A <chord/> note instead joins the previous attack. In scores with several voices, <backup> and <forward> move the source cursor.

Select a part or open a compressed score

In a long work, select the original part ID and inclusive measure positions. Position 1 means the first measure in the file, even if its printed number is 0. Compressed .mxl files have a separate asynchronous reader that opens the archive manifest. Pass it the original bytes.

Use the integration example to open the resulting document in an editor or validate it in Node.

Use an importer in your application

Load the reader for the file your user chose. Conversion produces editable VexTab text in Node or a browser worker. Your application can save that text, validate it without a browser, or open it in an editor.

Install the separate package

From a VexTab source checkout, build a local importer tarball. Install the resulting file in your application alongside a compatible VexTab host.

The public entries are vextab-import/lilypond, vextab-import/musicxml and vextab-import/mxl. Only MXL needs archive decompression. A dynamic import lets an editor wait until someone actually opens a source file.

Open the generated text

Check the result and target.minimumVersion before rendering. A compatible host can mount a Div in a connected HTML element. Node applications can import parseScore from vextab/parse to inspect the generated parts, voices and durations.

For substantial files, send the source to a worker and return the result to the UI thread. Use a part or measure selection to reduce the work. When a conversion requires capacity: 'large', enable the same capacity on the consuming parser or editor. See the embedding lesson for the editor lifecycle.

Read the diagnostics

Strict mode is the default. A faithful import returns exact. A known loss makes strict conversion fail. Partial mode can emit an editable score and a warning for each supported omission. An unresolved musical duration can make both modes fail.

ResultWhat your application receives
exactOne document and no known losses in the selected passage under the chosen profile. Page breaks, spacing and automatic engraving can differ between engines.
partialOne document and located warnings. Show the musician the affected passages before they accept the result.
failedDiagnostics and zero documents. Show the source location, then let the user correct the input or choose a supported passage.

On the LilyPond example, insert \break immediately after the first barline. Try strict conversion, then choose partial mode. The source requests a particular system break. Partial conversion keeps the two bars and reports the break.

Each diagnostic has a file name, message and half-open UTF-16 range. The part, measure and voice identify musical context when the reader knows them. With sourceMap: true, a document also records ranges for generated and original tokens. The reader can synthesize silence when a voice enters late, so some generated events have no source token.

Choose a target profile

The standard profile covers measured notes, rests, basic voices and rhythm. Extended adds timed clefs, keys, tempo, transposition and staff groups. Expressive adds per-head ties, lyrics, dynamics, harmony and instrument notation. The profiles begin at VexTab 6.2.3, 6.3.0 and 6.4.0 respectively. A score using newer features reports its own minimum, such as 6.6.0 for a named cross-bar beam.

The readers cover score-partwise MusicXML, selected MXL score members and static LilyPond music. Source material with arbitrary Scheme, filesystem includes, unsupported navigation or inconsistent written and elapsed timing can require re-authoring. The score gallery shows which losses remain in complete editions.

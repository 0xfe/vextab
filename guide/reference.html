Modules and entry points

vextab/parse

Use this module to validate music in Node.js or a worker. parseScore(source) returns a ScoreV2 document or throws ScoreV2Error. With { language: 1 }, the result is a ParsedScore and parse errors use ScoreError. Both CommonJS and ES module callers can use this entry.

import { parseScore } from 'vextab/parse';
const score = parseScore('meter 1/4 staff { C4 | }');

vextab/browser

Import Div to mount an editor on an existing element. For a separate preview, import parseScore and renderScore. The same entry exports part and conductor renderers, Player and its audio adapters, and the legacy Artist, VexTab and Vex objects.

import { Div, parseScore, renderScore } from 'vextab/browser';

vextab/performer

Use this entry to shape an existing performance without loading a browser renderer. createPerformer(nameOrProfile, seed?, swing?) defaults to the human profile. Supply the parts and bar data from your performance. Its perform(parts, bars, tempo) method returns the parts with performance timing and dynamics applied. Tempo defaults to 120 quarter notes per minute. A safe integer seed reproduces a take. An invalid seed throws RangeError.

import { createPerformer } from 'vextab/performer';
const take = createPerformer('parker', 42);
const played = take.perform(parts, bars, 132);

vextab/auto and script tags

The auto entry mounts each div.vextab-auto on DOM ready. Load dist/div.prod.js for a plain HTML page. The package root and dist/main.prod.js retain the legacy browser API. The old dist/vextab-div.js adapter supports .vex-tabdiv, underscore editor attributes and the original Canvas default.

<div class="vextab-auto" editor="true">guitar { 0/1 2/1 3/1 2/1 | }</div>
<script src="./div.prod.js"></script>

Parsing and the score model

parseScore(source)

Pass the VexTab source as a string. The default result, ScoreV2, retains that string and the music after pattern expansion. You can reuse the result for engraving, printing and playback. Enclose an intentionally incomplete phrase in fragment { … } to skip its bar-length check.

Note-mark aliases and comments

Declare an alias before the part that uses it. With alias v="vibrato" sd="stroke down", 5/3[sd] marks a downstroke and 2/2[v] marks vibrato. Each name expands to one built-in mark and can be reused across voices and parts.

Use # for a line of commentary or after the music. A sharp in F#4, a hex colour such as ink #abc, and text inside quotes keep their musical meaning. Play the example →

Same-string fret runs

4-5-6/3 plays frets four, five and six on string three. Each attack uses the current duration. In 4-5-6/3[vibrato] the vibrato belongs to fret six.

Meter by part

Declare meter 3/4 inside a staff or guitar part. Change it immediately after a barline, or declare meter 6/8 at 2 in the part header. A meter before all parts supplies their default. Compare two parts with different meters →

transpose

transpose takes a signed number of semitones before the first part. It shifts the key signature and sounding pitches while keeping guitar notes on their authored strings. If the new pitch would fall below an open string, choose another string in the source.

transpose +2
meter 4/4
guitar { key C :q 3/5 5/5 7/5 8/5 | }

This shifts C major to D major and displays frets 5, 7, 9, and 10 on string five.

Grammar v2

VexTab 6 selects grammar v2 unless the caller passes { language: 1 } to the parser or sets data-language="1" on the embed. For a complete bar, parseScore('staff { :w C4 | }').measureCount returns 1. To show rhythm in a guitar part, add tabStems on.

ScoreV2

Follow parts → staves → voices → events to reach a written attack. Each event records its onset, duration, heads and source range. Use that range with the original source string to recover the text the musician entered.

const event = score.parts[0].staves[0].voices[0].events[0];
const token = score.source.slice(...event.range);

ScoreV2Error and source ranges

Read line and column for a one-based location to display to the author. Use range for text selection. Its two offsets count UTF-16 code units from the start of the input and exclude the character at the end offset.

try { parseScore(input.value); }
catch (error) {
  if (!(error instanceof ScoreV2Error)) throw error;
  input.focus();
  input.setSelectionRange(...error.range);
}

Rendering and navigation

renderScore(host, score, options?)

Pass a host element, a parsed score and optional layout settings. The default renderer produces SVG. width is measured in CSS pixels and must exceed 20. It defaults to the host width, or 640 when the host has no width. Choose part: 'score' for the authored staves, 'notation' for the staff or 'tab' for the frets. Successful layout replaces the host contents and returns the composition, navigation data, hit regions and diagnostics.

const score = parseScore(input.value);
const view = renderScore(preview, score, { width: 640, part: 'tab' });

navigation.events and hitTest(x, y)

Use view.navigation.events to read labelled attacks in musical order. For a pointer selection, convert the screen position to SVG-local coordinates and pass them to view.hitTest(x, y). It returns the hit region, or undefined in empty space. A tie across a system break can occupy more than one region.

sourceFor(id) and rangeFor(id, source)

Pass a screen or print ID to sourceFor(id) to recover the shared musical ID. For an editor selection, pass the ID and the current source string to rangeFor. An unknown ID or a changed source string yields undefined.

const range = view.rangeFor(view.navigation.events[0].id, input.value);
if (range) input.setSelectionRange(range.start, range.end);

DOM embeds and live editors

new Div(host)

Pass an HTML element or a selector for a single host. Set the source using textContent before construction. Div reads the host attributes, draws the score immediately and adds a textarea when editing is enabled. Create one instance per host.

import { Div } from 'vextab/browser';
host.setAttribute('layout', 'flow');
host.setAttribute('editor', 'true');
host.textContent = 'meter 1/4 staff { C4 | }';
const editor = new Div(host);

Host attributes and defaults

Each setting accepts a data- prefix. For example, set data-layout="flow" data-editor="true" data-width="auto" for a responsive editor. A nonempty prefixed value takes precedence over the plain attribute. With automatic width, an authored layout { width 1460 scale 0.61 } engraves at 1460 pixels and displays the music at about 891 pixels.

layout, renderer, scale
Fixed layout defaults to SVG at scale 1 and also supports Canvas. Grammar v2 flow supports SVG and Canvas. Use data-view="conductor" to align all instruments.
width
Fixed defaults to 400 px. A flow host with an omitted width or width="auto" follows its container.
editor, show-errors
Set editor="true" to expose the source textarea. show-errors="true" displays diagnostics without the editor.
editor-width, editor-height
Pixel dimensions. Defaults are the score width and 200 px high. The historical adapter also accepts editor_width and editor_height.

run(), redraw(), parse() and draw()

Call run() to apply a pending textarea edit immediately. Ctrl+Enter or Command+Enter does the same. Call redraw() to parse and draw the stored source again. For separate steps use parse() and draw(). Each returns the editor. An invalid edit displays a diagnostic and leaves the last valid score visible.

setPart(part) and setWidth(pixels)

Flow-only methods that return the editor. Select a staff or reflow the same parsed revision without rewriting the source. Setting a width explicitly takes over from automatic container observation.

getScore(), getReadingEvents() and selectSource()

getScore() returns the current valid flow revision or undefined. getReadingEvents() returns the current reading order, or an empty array when unavailable. selectSource(id, revision) focuses the editor and selects the matching token. It returns false for a stale revision or missing selection.

const revision = editor.getScore();
const [first] = editor.getReadingEvents();
if (revision && first) editor.selectSource(first.id, revision);

setInstrumentView(target, staff?) and getScoreDocument()

Choose 'conductor' or a selector such as { partId: 'cello' } on a v2 editor. The optional staff selects notation, TAB or a piano hand. The editor keeps the current source. getScoreDocument() returns the complete current parsed document, including when the selected layout cannot share a bar grid.

const editor = new Div(host, { view: 'conductor', player: true, order: 'performed' });
editor.setInstrumentView({ partId: 'cello' });

getDiagnosticRange() and selectError()

Read the located error in the current edit or select its characters. getDiagnosticRange() returns undefined for a valid score or an obsolete diagnostic. selectError() returns whether the editor could select the range.

vextab-render and dispose()

Listen for vextab-render on the host to refresh controls after an engraving attempt. Call editor.dispose() before unmounting. It disconnects resize observation and cancels pending editor work. The host application owns its DOM and its own event listeners.

Publication and export

renderConductor() and renderEdition()

Use renderConductor for a screen view that aligns the instruments in written pitch. Use renderEdition for the conductor’s print edition or an individual part. The source supplies breaks, turns and cues. A paper size in the options overrides the source for that export. Inspect result.diagnostics for the affected measure and source range.

const score = parseScore(source);
renderConductor(preview, score, { width: 800 });
const result = renderEdition(paperHost, score, { partId: 'cello' }, { paper: 'Letter' });

Read the edition example

renderScorePart(host, score, staff, options?)

Independently engrave 'notation' or 'tab' from the same parsed score. Omit voice to retain every voice on that staff, or pass a one-based voice number. Choose paper: 'A4' or 'Letter' and set a title. The result includes the selected score, its publication, sourceFor and rangeFor.

const { publication } = renderScorePart(paperHost, score, 'notation', {
  voice: 2, title: 'Guitar 2', paper: 'Letter'
});

PublicationResult.pages, diagnostics and toPrintHTML()

Each page has an SVG and its musical metadata. Inspect publication.diagnostics for overflow and engraving details. Supply matching outline fonts to toPrintHTML(faces) for an offline print document or toSVG(pageNumber, faces) for a single outlined page. Page numbers start at one. The guide loads matching outlines for Bravura with Academico or Petaluma with Petaluma Script.

Piano grand staff and hand parts

Put upper { … } and lower { … } inside a piano part. Both hands share the meter, keys and bar boundaries. The hands share space where their notes and expression marks fall on different beats. Marks above and below the same beat open the gap as needed. To request more room, set a minimum with layout { staffDistance 14 }, measured in staff spaces from one top line to the next. A hand can contain several named voices. Set stem up and stem down for opposing stems.

In the opening of Liszt’s Consolation No. 5, the crescendo belongs to the bass melody and appears between the hands. Write crescendo above { … } in the lower voice to do the same. The formatter leaves room for the hairpin over the beats it spans, while a direction such as dolce can use the same space later in the phrase. Read the Consolation score.

Use layout="flow" for an SVG embed. Modern and legacy embeds initially containing a piano declaration also select flow automatically. For a programmatic score, pass parseScore(source) to renderScore or Player. Pass part: 'left' or 'right' to show one hand. The reader and playback follow the visible hand in an embed.

renderScorePart(host, score, 'notation') prints both staves. Use 'right' or 'left' for a practice part. The optional voice number selects one voice within that hand. Native part engraving limits also apply to piano. Try two-hand and four-voice examples.

Grace chords, ossias and sustain pedal

Put a grace group on the principal note. Each pitch in the group gets a separate attack unless you enclose pitches together as a chord. In the example, G and B sound together just before C. slashed draws the stroke through the grace stem. Guitar groups can use frets such as 0/1[finger i above] to place each grace on a string and name the picking finger. Grace notes borrow time from the principal. An ossia gives the player an alternative in small notation below the anchor. Playback uses the main reading.

meter 3/4
piano {
  upper { :q C5[grace before slashed ((G4 B4))] D5 E5 | }
  lower { :q C3[pedal down] G3[ossia :8 (G3[ornament mordent] F3 G3)] C4[pedal up] | }
}

Place pedal down and pedal up in the same piano voice. The pedal sustains both hands from the first marked attack through the end of the release note or rest. Follow the pedal changes in Chopin’s Ballade.

Score heading and optical spacing

Set layout { font Petaluma } for handwritten music with Petaluma Script lettering. Both screen and print use the pair. Choose font Bravura for Bravura music and Academico lettering. Read Pocket Change in Petaluma.

Neighboring piano systems also share space. A high note can rise beside an ossia or between pedal symbols on the system above. Increase layout { rowGap 48 } for more separation on screen.

The first system can carry a centered title, a left dedication, an indented tempo and a right-aligned composer. Each field is optional. Use heading { align center title "Soleá" composer "Traditional flamenco" } to stack the heading lines at the top, above a centered key of chord diagrams. Set firstSystemIndent in engraving pixels to inset the opening system. Later systems return to the usual margin. The indent counts toward the width available for notes on screen and in print. Use ^{me} for a raised ordinal. Optical spacing distributes room according to note duration and measured ink.

layout {
  spacing optical firstSystemIndent 80
  heading { title "3^{me} Ballade." tempo "Allegretto." composer "Fr. Chopin, Op. 47." }
}

Independent part coverage

Printed parts preserve explicit beams, silent beats, chord diagrams, forced accidentals and head fingerings. Lyrics in a voice share a baseline across a system. Use distinct named verses for two underlays. A duplicate lyric in the same lane produces a diagnostic at the second mark. TAB retains fingerings beside the selected fret. Selecting a voice missing from a bar also produces an error.

Free-form examples

Use fragment { … } when the excerpt starts or ends with an unfinished measure. In the example below, two quarter notes are enough to render the sketch. The host supplies the drawing element.

Render into SVG or Canvas

Change the view

To fit a new width, call renderScore again with the parsed score and the new width in CSS pixels. On a flow editor use editor.setWidth(pixels).

Playback and instruments

Player, tempo and instrument

Pass a ScoreV2 to new Player(source, options). Call play() from a user gesture. Its promise resolves at the end or on Stop and rejects on audio errors. stop() cancels a pending load and releases sounding notes. dispose() also removes controls. setTempo(bpm) changes the tempo during playback. setInstrument(program) stops the current performance.

Tempo defaults to 120 quarter notes per minute. Set a General MIDI program from 0 to 127 or a name such as acoustic_guitar_nylon. The default performer is human. Other presets are bach, chopin, parker, ragtime, blues and robot. Use swing eighths for a printed swing equation and long–short playback, or swing off for straight eighths. A host can override the performer and pass an integer seed to reproduce a take. Compare performers on the same piano chords.

createWebAudioPlayback() and createSpessaSynthPlayback(synth, channels?)

Use the default Web Audio adapter for a synthesized tone that needs no sample files. To play a SoundFont, load the matching worklet and bank, connect the synth to an output and pass it to createSpessaSynthPlayback. Reserve channels for the adapter so one string can bend while another holds a steady pitch. Load a SoundFont and connect the score.

const playback = createSpessaSynthPlayback(synth);
const editor = new Div(scoreHost, { playback, player: true });

player: true enables the sheet controls even for source without a player directive. Use playbackControls on Div or controls on Player to pass false, a toolbar element, or an object with visibility (hover, always or off), size (auto, mini or large), position and inset. Large is the default. Auto-scroll starts on and follows the playing system. Auto selects the large panel for a scrolling score or one at least 80% of the viewport height. Both control sizes default to bottom-center with a 12-pixel inset from the visible sheet. Positions combine top or bottom with left, center or right, such as top-right. Custom instruments implement PlaybackPlugin.open(program, signal) and return a session with playNote(note) and stop().
